# HTML 浏览器、编辑器与玩法系统

本文件是项目设计建议，不是任何公司的内部架构规范。已有实现优先沿用；只修改与当前任务有关部分。

## W01 渲染与屏幕

- HTML 是运行环境，不意味着每个地块都必须是 DOM 节点。大地图可选 Canvas 2D / WebGL 或现有2D框架；编辑器面板、对话、收集册优先使用易访问的 HTML 控件。已有可靠 DOM 方案不必强制迁移。
- 分开记录：原生素材像素、世界坐标、相机坐标、逻辑渲染分辨率、CSS尺寸、Canvas backing store及devicePixelRatio。禁止把“1440p”直接当物体大小或触控尺寸。
- 对像素场景使用明确采样策略；Canvas 2D 的 imageSmoothingEnabled 与 CSS image-rendering 分别影响不同缩放环节，仅设置CSS不能保证内部绘制不模糊。[来源 S6](sources.md)
- DPR 缩放和低分辨率渲染目标是两种需协调的策略，不能重复放大。先画低分辨率场景再放大时，UI可以保持独立高分辨率。
- 世界物理位置保留小数，最终绘制位置按策略吸附；不要逐帧把物理位置取整导致慢速移动停止。相机平移也参与像素对齐。
- 指针坐标从client坐标扣除元素位置，经CSS缩放、留黑、视口和相机逆变换映射回世界；浏览器缩放、DPR与编辑器zoom后仍应点中同一格。
- 屏幕尺寸变化后重设缓冲区及绘图状态；严格整数缩放可能出现留黑，是否扩展可见地图范围需明确。不得裁掉关键UI。
- 通过HTTP(S)本地服务器开发；资源失败给占位及错误。跨域图片、Canvas导出与音频播放限制要在部署域验证，不默认file://行为等同线上。

## W02 人物移动与输入

- 用时间计算位移，速度单位为世界像素/秒或格/秒；requestAnimationFrame回调频率不等于固定60Hz。[来源 S7](sources.md)
- 固定步长模拟或带上限的delta均可，但写明长帧恢复策略。大delta不能让角色穿墙；高速移动用子步或连续检测。
- 斜向移动归一化；碰撞使用脚部实体，与树冠可视范围分离。明确格子移动或连续移动，不混用两套坐标。
- 定义idle/walk/interact等状态及输入优先级；对话、收集册和编辑器输入框获得焦点时，游戏快捷键不应继续移动人物。
- blur、visibilitychange、pointercancel和触摸中断清空按键/摇杆状态，避免回来后持续走路。
- 支持的输入方式必须分别测试：键鼠、触控、手柄按实际范围选。移动端区分拖拽镜头、移动和点击物件；不让触控误触穿透UI。
- 有点击寻路时，建筑放置/删除会更新导航；目标入口不可达给提示，NPC互相阻挡要有处理策略。

## W03 编辑器与运行时共用内容

分离三个对象：内容定义（地图/资源/事件/收藏条目）、编辑器会话（选区/历史/面板）、玩家状态（位置/时间/奖励/收藏）。预览从内容快照创建独立状态，退出预览不得改正式存档。

编辑器与运行时共用数据格式、ID、坐标转换、碰撞/排序及条件解释。不要编辑器允许一套规则，运行时再猜另一套。

必备能力按任务实现：

1. 图层显隐/锁定、网格吸附、多选、撤销重做、素材目录与搜索；一次拖拽为一次撤销操作，避免每像素记一条。
2. 可视化占地、碰撞、交互区域、排序锚点、入口、事件区域及导航通路；早中晚预览独立于游戏时钟。
3. 地图实例使用instanceId，资源使用assetId；复制实例生成新ID，不改变所引用的资产。事件和收藏引用稳定ID，不用数组下标或显示名。
4. 导出保存schemaVersion和contentVersion；导入校验类型、数值范围、重复ID、悬空引用、地图边界、资源路径、未知动作、文件大小与对象数量上限。
5. 合法导入后再替换内容；失败不破坏当前地图。自动存草稿和手动导出并存，撤销历史与玩家存档分开。
6. 删除被引用对象时显示依赖；提供修复/重定向或明确移除引用，不留下静默失效事件。
7. 地图JSON只允许数据和白名单条件/动作，不接受eval、Function或任意脚本字符串。描述文字按文本显示，外部资源路径和URL按项目允许范围验证。

放置模式必须声明唯一权威坐标。网格模式以placementCell加明确anchorOffset推导worldAnchor；连续摆放以worldAnchor为准，由局部占地形状变换后覆盖的格子计算导航占用。两者不可各自编辑后失配；锚点恰落格线时不能直接floor推断归属。方向/变体必须携带对应pivot、占地、碰撞、交互与排序数据，或者显式继承同一几何。切换前验证目标占地与玩家位置，失败保留旧状态。

## W04 事件触发与奖励

每个事件定义：eventId、触发来源、条件、动作列表、执行顺序、优先级、重入策略、重复策略、失败行为、状态作用域和版本迁移关系。

- 区分enter/exit/interact/timePhaseChanged/collectionChanged等触发器；角色仍停在区域内不是每帧重新enter。
- once-per-save、once-per-day、cooldown、repeatable是不同语义；必须选定。地图重载和读档是否重新enter需要明确。
- 使用当前世界状态判断条件；条件与动作分开。事件触发其他事件时限制深度/次数并提供日志，防止循环。
- 对话等异步动作明确等待、取消和失败时是否继续后续动作；禁止双击启动两条相同奖励链。
- 一次性奖励以稳定eventId加作用域键做幂等标记。收藏解锁、背包增量和事件完成标记应在一次逻辑事务中更新并一起持久化；失败不留下“领取标记已写但物品没到”的半状态。
- 每日事件的键包含游戏dayIndex；循环奖励需独立实例键。读档不会把已领事件变成未领。
- 纯本地游戏可以保证单个存档内一致性；涉及服务器经济时，以服务端事务/幂等为准，客户端标记不构成防作弊保证。

每个异步事件声明条件在触发时锁定还是提交前重验；默认建议提交前重验时间条件、目标存在和领取资格，失败不提交奖励。不同事件修改同一存档时通过统一状态提交队列串行化，在事务内重新检查完成键和收藏状态，避免两个事件都发首次奖励；UI动画不阻塞整个状态队列。

## W05 早、中、晚与昼夜

先明确时间来源：游戏内模拟时间、真实时间或剧情推进。默认建议游戏内模拟时间，隐藏标签页时暂停；这不是已获用户确认的玩法。

- 建立唯一WorldClock：dayIndex、dayLength、elapsed、timeScale及暂停状态。phase由时间映射推导，避免各系统各自setInterval。
- 用可配置且不重叠的半开区间定义早/中/晚，例如一天模拟600秒：[0,200)、[200,400)、[400,600)。这只是示例，不代表现实日出日落；要第四个“夜”阶段时显式新增。
- 渲染、商店营业、NPC日程、收藏刷新和事件条件读取同一phase。UI颜色不能充当时间状态。
- 逻辑阶段在边界切换一次；美术可渐变到目标色，光照插值不得每帧再次派发阶段事件。
- 大步跳时、睡觉、恢复后台时明确：逐个补发跨越边界，或只结算最终状态。用例必须覆盖跨多阶段和跨日；奖励不能因补发重复。
- 浏览器会节流后台计时器，rAF通常暂停；恢复时重置上一帧时间基准。真实时间玩法另需处理时区、系统时钟回拨与离线收益上限。[来源 S7/S8](sources.md)
- 早晨、正午、晚间分别验证角色、可交互物、路径和文本的辨识度；环境染色不影响UI可读性，窗灯按独立层控制。
- 玩家进入对话/收集册时世界是否暂停、暂停期间哪些效果继续，写成同一张状态策略表。

## W06 收集册、背包与存档

CollectionDefinition定义collectionId、名称文本键、分类、图标、发现/收集条件、说明、排序和奖励；PlayerCollection保存发现时间、收集状态/次数、首次来源、新条目标记、领奖状态。

- 背包记录当前拥有数量；收集册记录历史达成。卖掉、消耗或丢弃物品不会自动抹掉已收集条目，除非玩法明确如此。
- 同一collectionId的重复拾取按规则加数量，不重复首次解锁奖励。地图实体使用独立instanceId区分同种物品多个实例。
- 收集成功、首次解锁、领取奖励分别有反馈；红点只表示未读/可处理状态，不在每次打开时全部重建。
- 收集册提供分类、详情、进度、空态和返回方式；键盘焦点、文字缩放、长中文及触控均需检查。大量条目再考虑分页/虚拟列表。
- SaveGame存schemaVersion、contentVersion、玩家位置、WorldClock、事件完成键、收藏状态和必要背包状态；运行时引用使用稳定ID。
- 小原型可存localStorage中的单个版本化快照；较大结构或多表事务可用IndexedDB。保存确认在写入成功后显示，处理不可用、配额不足和损坏数据。[来源 S9](sources.md)
- 自动保存由有意义的状态变化驱动并适度合并；不每帧同步写localStorage，也不只靠unload保存。
- 版本迁移先备份，失败保留旧档；新增收藏条目补默认值，移除/改名条目提供ID映射。未知未来版本不能静默清空。
- 浏览器本地存储不是云备份，换域/清理数据/设备变化可能无法读取；提供导出导入入口。多标签页采用单写者或明确冲突处理，避免互相覆盖。

## W07 性能与内容预算

预算需注明目标设备、浏览器、DPR、地图规模和测试过程；没有这些数据，不承诺固定帧率、NPC数量或内存上限。

按内容分块加载与视口剔除；注意透明树冠overdraw、灯光层、地图重绘、NPC寻路与每帧分配。纹理压缩文件大小不等于解码内存，RGBA8基础像素内存可按宽×高×4字节估算，还要计副本、图集与渲染目标。

建议记录加载时间、长帧、p95帧耗时、内存变化和连续操作后的增长。60fps约16.7ms是单帧时间换算，不是无需实测的性能承诺。先实测热点再选择分块、缓存、对象池或Worker，不一次堆满优化架构。
