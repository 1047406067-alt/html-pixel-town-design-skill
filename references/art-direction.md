# 美术风格与素材交付

以下除明确引用外，均为本技能提出的项目规范。采纳后作为团队统一约定；已有项目用现有基准替换建议值，不强制重绘。

## A01 风格基准板

量产前建立同屏基准板：角色、门、建筑、树、地面、水边、图标、对话框；每类至少一个代表。记录版本，采购、外包和 AI 生成均对照同一版。

| 维度 | 必填内容 | 验收方法 |
|---|---|---|
| 视角 | 斜俯视/正俯视/等距之一；屋顶和侧面可见程度 | 同屏对照门、桌面、角色头顶 |
| 网格 | 格子边长、逻辑占格规则 | 地形接缝与建筑入口对齐 |
| 像素密度 | 原生像素到世界单位比例；缩放策略 | 原生尺寸和运行尺寸观察像素颗粒 |
| 比例 | 角色身高、门洞、树干、桌椅关系 | 实际过门和坐/站对比 |
| 色彩 | 命名色板及色值、材质明暗色阶 | 同材质归并；不是所有物体用同一颜色 |
| 描边 | 外轮廓粗细、颜色、内部线条规则 | 不混用硬黑边、软描边和无描边体系 |
| 光照 | 主光方向、阴影颜色与强度 | 轮廓和落地阴影一致 |
| 细节 | 地面/角色/交互点的细节优先级 | 背景不掩盖角色与入口 |
| 动画 | 动作帧时长、脚底锚点、运动节奏 | 循环无跳位，行走与位移匹配 |
| UI | 面板、图标、字体和状态表现 | 同类交互用同样视觉语言 |

建议起点：32×32 原生像素地块、角色可先试 32×48 画布、固定斜俯视、建筑单朝向、地面低对比、关键交互高辨识度。它们是样板参数，不是从截图测出的数据，也不是大厂规定。画布包含透明边距，不等于人物实际身高。

16px 地块与32px人物不必然冲突：先核对世界比例和每个可见像素的尺寸；把16px画面放大两倍可能形成2×2像素块，与原生32px细节不一致。允许有意设计的分层密度，但须写明范围并在样板中验证。

## A02 素材拆分与连接

- 地形：草地、土路、水面、河岸分开；根据选定自动铺砖规则提供直边、内角、外角、端点、孤立块、窄通道和必要的交叉连接。具体数量取决于邻接算法，不统一硬写“必须47张”。
- 树木：基座、树干、树冠、阴影按遮挡需要拆分；建筑的屋檐、屋顶、门、发光窗和招牌按交互需要拆分。别为了分层而过度拆图。
- 四方向建筑分别绘制所需视图；镜像前检查文字、结构、主光和落地阴影。纯地面图案的90°旋转与建筑换朝向不是同一问题。
- PNG/无损格式可作为默认；普通角色和物件保留透明背景。明确边缘是否允许半透明，不用“所有像素只能不透明”限制灯光和烟雾。
- 帧图保留统一画布或完整裁切偏移；自动裁切后缺少偏移会导致人物抖动。
- 图集留边、边缘扩展、采样与压缩要一起验证，不能只靠“加1px边距”保证无渗色。图集尺寸依据目标设备，不要求每张独立精灵为2的幂。

## A03 资源交付合同

每项资产至少包含以下字段，静态物件无动画时明确写 none：

| 字段 | 约定 |
|---|---|
| assetId / revision / styleVersion | 稳定资源 ID、资源版号、对应风格版号；文件更名不改变语义 ID |
| source / license | 制作者、来源、商用与修改范围、署名要求、授权记录；AI 辅助另记工具和生成条件 |
| sourceFile / runtimeFile | 可编辑源文件与实际发布文件；缺源文件注明限制 |
| canvasPx / atlasRect / trimOffsetPx | 原始画布、图集区域、裁切后在原图中的偏移 |
| coordinates | 像素原点、轴向、单位、pivot 定义、世界映射；不可只写“脚底” |
| footprintCells | 放置占格和格子锚点；与图片范围分别记录 |
| collision / interaction | 形状、坐标空间、通行规则和交互距离；不直接照搬精灵矩形 |
| sortAnchor / layers | Y 排序锚点、地面/主体/前景层关系和遮挡拆分 |
| directions / animation | 可用朝向、帧顺序、每帧毫秒数、循环与事件帧 |
| variants | 昼夜、季节、成长、升级、破损和服装的实际支持矩阵 |
| importProfile | 采样、缩放、颜色处理、透明处理、图集分组 |

所有资源都用同一坐标规范；推荐原图左上为原点、x向右、y向下、单位原生像素。世界坐标与屏幕坐标另行标注。详见[示例](example.md)。

## A04 角色、昼夜、收藏图标

- 最低角色动作由玩法决定，通常先做四方向待机/行走；采集、对话表情、受击等按已确定玩法增加。左右动作只有在视觉对称时复用。
- 帧数预算按实际组合统计：方向×动作各自帧数，再计服装层与状态。不是所有组合都需重画，也不能默认全部免费复用。
- 昼夜优先复用基础图，加环境调色、阴影强度和独立发光层。固定画死的强烈太阳阴影与可旋转太阳矛盾，需选择一种光照策略。
- 雪层、窗灯和特效独立叠加；早、中、晚各检查角色轮廓、入口、收藏物。夜景不能仅靠全屏黑色遮罩。
- 收藏图标沿用材质色与轮廓语言，可单独重构小尺寸细节，不把大建筑简单缩小当图标。
- 收集册区分未知、已发现、已收集、奖励可领/已领；是否展示未知轮廓由剧透策略决定。

## A05 视觉与交互避坑

借鉴 Riot 对信息层级、轮廓与低噪声的公开讨论：优先让玩家识别自己、目标、入口和交互反馈。这是对小镇玩法的迁移，不照搬竞技技能的视觉强度。[来源 S1](sources.md)

- 不把所有花草做成高饱和、高对比或持续闪烁；保留道路与门前净空。
- 点击命中区可大于物件图像，但必须处理相邻命中区的竞争；触控长按提示不能成为唯一入口。
- 用图标/文字/形状补充颜色；可领取、被锁定、任务提示不能只用红绿差别。[来源 S4](sources.md)
- 字体覆盖中文与其他目标语言；正文不为像素气氛牺牲可读性，可提供清晰字体和文字缩放。[来源 S2](sources.md)
- 普通关键文本对比度参考 XAG 102 的4.5:1，按最不利背景测量；大型文本等有不同适用条件。不要把此阈值套到所有树叶和装饰纹理。[来源 S3](sources.md)
- 关键信息文字用可本地化文本层，不写死在背景 PNG；UI缩放独立于世界像素缩放。

## A06 采购、AI 与扩产

先检查授权和风格，后购买/量产。参考图可用于风格分析，不直接拆取第三方角色、建筑或商标。AI 输出也要检查许可条件、像素网格、透明边缘、重复纹样、朝向和帧间一致性；提示词一致不等于成品一致。

量产前列素材×朝向×动作×时段×季节×升级×服装矩阵，标出原图复用、叠加层、独立重绘和不支持。以代表资产实测制作与返工时间估算，不编造固定工期。
